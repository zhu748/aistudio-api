# 调用统计与请求排查

控制面板的调用数、成功率和 Token 来自请求历史。每次客户端调用按最终结果计一次：先收到 429、切号后成功，计为一次成功调用，同时记为两次上游尝试和一次发生重试的调用。账号调度器仍保留独立的调度事件计数，用于冷却和选号。

## 单次调用详情

在「请求记录」点击「查看」，可查看：

- 客户端模型与实际模型、最终服务账号、协议、密钥标识、代理和签名节点。
- 客户端指定的思考强度或预算，以及实际发送的思考配置、Temperature、Top P、Top K、输出 Token 上限。
- 首包、首次思考输出、首段回复和总耗时；输入、输出、思考、缓存和总 Token。
- 执行时间线、逐次上游尝试及按 Request ID 关联的日志。
- 按需采集的脱敏请求与响应正文，以及独立详情链接和 JSON 导出。

首包指首次向客户端发送响应数据；首段回复指应用首次收到正文、图片或工具调用。思考输出单独计时。非流式和缓冲流式请求需等待完整内容，不能据此推断模型内部开始生成的时刻。上游未返回的用量显示为「—」，旧请求不会补造缺失参数。

请求参数采用白名单采集，无需开启正文转储。完整正文仍由日志设置中的文件转储开关控制，沿用脱敏、大小和保留期限限制；流式响应正文不持久化。

## 日志分类

运行日志默认打开「模型请求」，包含调用过程及相关签名、传输、切号错误。「系统日志」包含启动、后台任务、配置和管理操作。两种分类均支持实时与历史查询，并可按模型、账号和 Request ID 筛选。

实时缓冲与文件归档都是有界的，早期日志可能已轮转。旧归档没有分类字段，归入系统日志，可通过「全部日志」查找。

## 时间范围与保留

控制面板支持今日、24 小时、7 天、14 天和自定义范围。统计覆盖请求历史的实际保留范围，受 `AISTUDIO_HISTORY_DAYS`（默认 14 天）和 `AISTUDIO_HISTORY_MAX_ROWS` 限制；清空已完成请求历史会清空对应统计。原有累计统计文件继续保留。

执行中的请求显示在单独区域，不进入已完成调用成功率。请求开始时先落盘，正常结束更新同一条记录。服务启动会将上次未完成的记录标记为「服务中断」；无法确定的耗时保持未知。此恢复方式适用于当前单进程服务启动模式。

账号今日用量使用美西日期，与控制面板的本地日期筛选不同。本地参考额度来自配置，用于调度；进度条不代表上游实时剩余额度。今日累计 429 与连续限流控制计数分开，成功调用和清除冷却不会清零今日累计值。升级前已被清零的历史限流无法恢复。

## 管理接口

所有接口继承控制台鉴权：

| 接口 | 用途 |
|---|---|
| `GET /api/requests/stats?since=...&until=...` | 最终结果统计，含模型、账号、密钥分布、趋势与 P50/P95 |
| `GET /api/requests/active` | 当前进程执行中的调用 |
| `GET /api/requests/options` | 模型、账号、密钥标识筛选选项 |
| `GET /api/requests/{request_id}` | 单次调用元数据 |
| `GET /api/requests/{request_id}/payload` | 脱敏正文与采集状态 |
| `GET /api/logs/stream?category=model` | 模型请求实时日志 |
| `GET /api/logs/history?category=model&request_id=...&order=asc` | 调用关联归档日志 |

`/api/requests` 与导出接口支持 `model`、`account_id`、`key_id`、`protocol`、`result`、`since`、`until`、`search`，以及 `retried=true`、`min_elapsed_ms`；`result=failed` 查询全部未成功调用。

`/stats` 为兼容现有客户端保留原有调度/重试事件累计口径。新控制面板使用 `/api/requests/stats`。日志接口默认分类改为 `model`，需要原先全部日志的客户端应显式传 `category=all`。
